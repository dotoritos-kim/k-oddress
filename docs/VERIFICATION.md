# 실제 주소 DB로 한 검증 기록

공개 주소 DB 전체분을 받아 이 저장소의 스키마에 그대로 넣고, API를 띄워 검색과 집계를 확인한 기록이다.

## 검증 환경

| 항목 | 값 |
|---|---|
| 데이터 | 주소기반산업지원서비스(business.juso.go.kr) 주소DB 전체분, 2026년 10월 31일 기준 |
| 건수 | 도로명코드 372,379, 주소 6,426,585, 지번 8,198,279, 부가정보 6,426,585 |
| DB | PostgreSQL 18.6, 인코딩 UTF8, LC_CTYPE ko_KR.utf8, shared_buffers 2GB |
| DB 크기 | 4.4GB (인덱스 포함) |
| 서버 | NestJS 11, Prisma 6, Node 22, 같은 장비에서 HTTP로 호출 |
| 장비 | Intel Core Ultra 7 265K, 메모리 30GB, NVMe |
| 측정 | 검색어마다 7번 호출한 중앙값, page=1, limit=10, 캐시가 데워진 상태 |

## 적재

`개선_도로명코드_전체분.txt`, `주소_*.txt`, `지번_*.txt`, `부가정보_*.txt` 네 묶음의 열 수(17, 11, 11, 9)와
순서가 `prisma/schema.prisma`의 네 모델과 일치했다. cp949 원문을 UTF-8로 바꿔 COPY로 넣었고, 길이 초과나
키 충돌 없이 38초에 끝났다. 적재한 건수는 압축 파일 안의 자료건수 문서와 같다.

## 찾은 결함과 고친 것

실제 데이터를 넣고 서버를 띄우자 드러난 문제들이다.

| 결함 | 증상 | 조치 |
|---|---|---|
| `searchService`에 `@Injectable()` 누락 | PrismaService가 주입되지 않아 모든 검색이 500 | 데코레이터 추가 |
| 응답 타입이 `string`인데 DB는 `null` | 리가 없는 주소에서 typia 응답 검증 실패로 500 | 선택 필드를 `string \| null`로 |
| 도로명코드만으로 조인 | 읍면동 일련번호를 빼서 같은 주소가 읍면동 수만큼 중복. "세종대로"가 306건이 아니라 2,343건 | 도로명코드 + 읍면동 일련번호 복합키로 조인 |
| 지번을 전부 조인 | 관련 지번 1,771,694건 때문에 한 주소가 여러 줄 | 대표 지번(`representative_YN = '1'`)만 조인 |
| `\|\|` 문자열 결합 | 읍면동이 NULL인 도로명코드 174,478행은 검색식 전체가 NULL이 되어 걸리지 않음 | `COALESCE`로 감쌈 |
| 정렬 없는 LIMIT, OFFSET | 페이지 사이에 같은 주소가 겹칠 수 있음 | 관리번호로 정렬 |
| 표시 주소 | 부번이 0이어도 "110-0", 시군구가 없는 세종시는 공백 두 칸, 지하 건물 구분 없음 | 부번 0 생략, `CONCAT_WS`, 지하와 공중 표기 |

## 검색 속도

원래 쿼리는 검색 때마다 주소 테이블 643만 행을 전부 읽었다(실행 계획의 Parallel Seq Scan, 버퍼 92만 개).
고친 쿼리는 도로명코드에서 트라이그램 인덱스로 도로를 고르고, 복합키 인덱스로 주소를 찾는다.
"테헤란로"의 개수 세기는 버퍼 520개, 0.5ms에 끝난다.

| 검색어 | 원래 건수 | 고친 건수 | 원래 | 고친 쿼리 | 고친 쿼리 + 인덱스 | 배율 |
|---|---:|---:|---:|---:|---:|---:|
| 세종대로 | 2,343 | 306 | 129.3ms | 334.0ms | 3.3ms | 39배 |
| 테헤란로 | 2,573 | 1,521 | 130.0ms | 331.8ms | 3.2ms | 41배 |
| Teheran-ro | 2,573 | 1,521 | 132.2ms | 331.0ms | 3.0ms | 44배 |
| 반곡동 | 5,267 | 1,472 | 141.1ms | 333.8ms | 2.9ms | 49배 |
| 역삼동 | 6,982 | 4,744 | 141.5ms | 337.1ms | 5.1ms | 28배 |
| 중앙로 | 218,964 | 77,321 | 402.8ms | 383.4ms | 69.7ms | 6배 |
| 해운대 | 7,293 | 2,141 | 154.5ms | 333.6ms | 3.6ms | 43배 |
| Gangnam-daero | 5,061 | 2,791 | 138.0ms | 333.9ms | 6.2ms | 22배 |
| 한누리대로 | 2,484 | 110 | 132.7ms | 329.9ms | 1.9ms | 70배 |
| 첨단 | 4,944 | 2,786 | 144.5ms | 336.6ms | 39.4ms | 4배 |

읽는 법:

- 조인만 고치고 인덱스가 없으면 오히려 느려진다(약 330ms). 복합키 조인이 인덱스 없이는 주소 테이블 전체를
  해시해야 하기 때문이다. 정확성 수정과 인덱스는 함께 들어가야 한다.
- "중앙로"처럼 7만 건이 걸리는 넓은 검색어는 개수를 세는 데 시간이 든다(69.7ms).
- "첨단"처럼 두 글자 검색어는 트라이그램을 만들 수 없어 도로명코드 37만 행을 훑는다(39.4ms).
- 한글 트라이그램은 DB의 LC_CTYPE이 C이면 동작하지 않는다. `show_trgm('세종대로')`가 빈 배열이면 로케일을 확인한다.

인덱스 크기는 `road_code_search_trgm` 28MB, `road_address_road_idx` 416MB다(`prisma/indexes.sql`).

## 집계

키 관계만으로 지역 단위 집계가 나오는지 확인했다. 시도별 주소 수는 16개 시도 모두 자료건수 문서와 일치했다.

| 집계 | 거치는 관계 | 시간 | 결과 |
|---|---|---:|---|
| 시도별 주소 수 | 주소, 도로명코드 (복합키) | 0.42초 | 16개 시도 모두 공식 건수와 일치 |
| 시군구별 주소 수 | 같음 | 0.48초 | 제주시 93,971, 경주시 77,830, 서귀포시 64,395 순 |
| 우편번호별 주소 수 | 부가정보 | 0.19초 | 우편번호 34,402개 |
| 행정동별 주소 수 | 부가정보 | 0.17초 | 행정동 3,621개, 평균 1,775건 |
| 시도별 공동주택 비율 | 도로명코드, 주소, 부가정보 | 1.64초 | 서울 20.4%, 인천 15.2%, 부산 8.1% |
| 법정동별 지번 | 지번 | 1.77초 | 법정동(리) 18,716개, 관련 지번 1,771,694건 |

집계는 643만 행을 전부 읽으므로 0.2초에서 1.8초가 걸린다. 화면에서 자주 부를 값이면 구체화 뷰로 미리 계산해 두는 편이 맞다.

## 다시 해 보기

```bash
# 1. 주소DB 전체분(주소기반산업지원서비스의 "주소DB")을 받아 한 폴더에 푼다
export JUSO_DIR=/path/to/juso
export DATABASE_URL=postgresql://user:pass@127.0.0.1:5432/koddress

# 2. 스키마 생성과 적재 (DB 는 LC_CTYPE 이 ko_KR.utf8 같은 UTF-8 로케일이어야 한다)
node verify/load.mjs

# 3. 인덱스
psql "$DATABASE_URL" -f prisma/indexes.sql

# 4. 서버를 띄운 뒤 측정과 확인
export API_URL=http://127.0.0.1:3000
node verify/bench.mjs after
node verify/check.mjs
node verify/stats.mjs
```
